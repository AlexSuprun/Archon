# 3.5 Logs and artifacts

What this answers: where run logs and artifact files live on disk, how to read them over HTTP, and what each workflow event type means.

## On-disk layout

For a codebase named `<owner>/<repo>` and run id `<id>`:

| What | Path |
|---|---|
| Project root | `~/.archon/workspaces/<owner>/<repo>/` |
| Source (clone or symlink) | `~/.archon/workspaces/<owner>/<repo>/source/` |
| Worktrees | `~/.archon/workspaces/<owner>/<repo>/worktrees/` |
| Logs dir | `~/.archon/workspaces/<owner>/<repo>/logs/` |
| Run log file (JSONL) | `~/.archon/workspaces/<owner>/<repo>/logs/<id>.jsonl` |
| Artifacts dir | `~/.archon/workspaces/<owner>/<repo>/artifacts/` |
| Run artifacts dir (`$ARTIFACTS_DIR`) | `~/.archon/workspaces/<owner>/<repo>/artifacts/runs/<id>/` |
| Web uploads (ephemeral) | `~/.archon/workspaces/<owner>/<repo>/artifacts/uploads/<conversationId>/` |

`$ARCHON_HOME` overrides `~/.archon`. The artifacts and logs trees are never in git.

## $ARTIFACTS_DIR

Pre-created by the executor before the run starts. Substituted into every prompt, command, bash, and script node. Use it as the canonical location for any file the workflow produces (plans, PRDs, RCAs, generated code patches).

```yaml
- id: write-plan
  prompt: |
    Write the plan to $ARTIFACTS_DIR/plan.md.
```

## Run log file

`<id>.jsonl` — one JSON object per line. Written by `@archon/workflows` logger. Use `jq` to read:

```
jq -c . ~/.archon/workspaces/<owner>/<repo>/logs/<id>.jsonl | less
```

## Reading artifacts over HTTP

`GET /api/artifacts/:runId/*`

| Behavior | Detail |
|---|---|
| Wildcard | Matches everything after `:runId/`, percent-decoded |
| `.md` content type | `text/markdown` |
| Other content type | `text/plain` |
| Path traversal | Any `..` segment → 400 |
| Null byte | → 400 |
| Leading slash / escaping the run dir | → 400 |
| Run not found | → 404 |
| Codebase missing or name not `owner/repo` | → 404 |
| File not found | → 404 |

The resolver derives `owner/repo` from the codebase name and joins with `getRunArtifactsPath(owner, repo, runId)`.

## Workflow event types

Defined in `WORKFLOW_EVENT_TYPES` (`packages/workflows/src/store.ts`). Every event is persisted to `remote_agent_workflow_events` and emitted on the SSE streams.

| Event type | When emitted |
|---|---|
| `workflow_started` | Run dispatch begins |
| `workflow_completed` | All terminal nodes succeeded |
| `workflow_failed` | A node failed and there is no recovery path |
| `workflow_cancelled` | Run was abandoned or cancelled |
| `workflow_artifact` | A node declared a produced artifact (path + label) |
| `node_started` | Node entered execution |
| `node_completed` | Node finished successfully (output captured) |
| `node_failed` | Node threw or returned a failing exit |
| `node_skipped` | `when:` evaluated false, or `trigger_rule` blocked it |
| `node_skipped_prior_success` | Resume found a prior `node_completed` and skipped re-execution |
| `loop_iteration_started` | Loop node started a new iteration |
| `loop_iteration_completed` | Loop iteration finished (completion signal or progressed) |
| `loop_iteration_failed` | Iteration errored |
| `tool_called` | Provider tool invocation started (Claude/Codex SDK) |
| `tool_completed` | Provider tool invocation returned |
| `approval_requested` | Approval gate paused the run |
| `approval_received` | User approved or rejected (decision in `data.decision`) |
| `ralph_story_started` | Ralph-mode story start (story-driven runs) |
| `ralph_story_completed` | Ralph-mode story end |

The CLI's progress renderer (when `--quiet` is off) maps these to stderr lines:

| Event | Line shape |
|---|---|
| `node_started` | `[name] Started` |
| `node_completed` | `[name] Completed (<duration>)` |
| `node_failed` | `[name] Failed: <error>` |
| `node_skipped` | `[name] Skipped (<reason>)` |
| `approval_pending` | `[id] Waiting for approval: <message>` |
| `tool_started` | `[step] tool: <name> (started)` (only with `--verbose`) |
| `tool_completed` | `[step] tool: <name> (<ms>ms)` (only with `--verbose`) |

Workflow-level, loop, artifact, and cancelled events are not printed to stderr by default — read the JSONL log or watch the SSE stream.

## Custom events from inside a node

A `bash:` or `script:` node can emit a workflow event:

```
archon workflow event emit --run-id "$WORKFLOW_ID" --type workflow_artifact \
  --data '{"path":"plan.md","label":"plan"}'
```

`--type` must be a member of `WORKFLOW_EVENT_TYPES`. Invalid JSON in `--data` produces a warning and the event is sent without a payload.
