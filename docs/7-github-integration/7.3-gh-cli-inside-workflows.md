# 7.3 — `gh` CLI inside workflows

What this answers: how to read GitHub state and write back to it from `bash:` and `script:` nodes.

## Why `gh`

`bash:` and `script:` nodes have no AI. They run as plain subprocesses inside the run's worktree. Anything `gh` can do, a node can do — auth, pagination, JSON output, GraphQL — without burning tokens or trusting an agent to format an API call correctly.

## Auth model

Archon does **not** inject `GITHUB_TOKEN` into `bash:` / `script:` subprocess env unless you put it in the codebase's per-project env vars (see module 2.4). In practice:

| Surface | Auth `gh` uses |
|---|---|
| CLI run (`archon workflow run …`) | Your local `gh auth` (the user keyring) |
| `@archon` mention on GitHub | The same shell env the server runs under. Set `GH_TOKEN` / `GITHUB_TOKEN` for the server process, or store it as a per-project env var |
| Web UI run | Same as the server process |

Inside a worktree, `gh` resolves the repo from the git remote automatically — no `--repo` needed for the current repo. For cross-repo calls, use `--repo owner/name`.

`stdout` of a `bash:` or `script:` node is captured and made available to downstream nodes as `$<nodeId>.output`.

## Quick reference

| Task | Command |
|---|---|
| Read issue body + metadata | `gh issue view $ARGS --json number,title,body,labels,assignees` |
| Read PR + files changed | `gh pr view $ARGS --json number,title,body,headRefName,baseRefName,files` |
| PR diff | `gh pr diff $ARGS` |
| Post issue comment | `gh issue comment $ARGS --body-file $ARTIFACTS_DIR/reply.md` |
| Post PR comment | `gh pr comment $ARGS --body-file $ARTIFACTS_DIR/reply.md` |
| Open a PR | `gh pr create --base $BASE_BRANCH --head <branch> --title "…" --body-file …` |
| List failing CI runs for a PR | `gh run list --branch <branch> --status failure --json databaseId,name,conclusion` |
| Fetch CI logs | `gh run view <run-id> --log-failed` |
| Reply to a review thread | `gh api -X POST repos/{owner}/{repo}/pulls/{n}/comments/{cid}/replies -f body=…` |
| Resolve a review thread | `gh api graphql -f query='mutation { resolveReviewThread(input: {threadId: "…"}) { thread { isResolved } } }'` |

## Node examples

### Read issue context, capture as JSON for downstream nodes

```yaml
- id: fetch-issue
  bash: |
    gh issue view "$1" --json number,title,body,labels,assignees > "$ARTIFACTS_DIR/issue.json"
    cat "$ARTIFACTS_DIR/issue.json"
  output_format: json
```

`$1` is the first positional workflow argument (e.g. an issue number). Downstream nodes consume `$fetch-issue.output`.

### Open a PR after an implement loop

```yaml
- id: open-pr
  depends_on: [implement]
  bash: |
    git push -u origin HEAD
    gh pr create \
      --base "$BASE_BRANCH" \
      --head "$(git branch --show-current)" \
      --title "$(cat $ARTIFACTS_DIR/pr-title.txt)" \
      --body-file "$ARTIFACTS_DIR/pr-body.md"
```

### Post a comment back to the triggering issue/PR

```yaml
- id: reply
  depends_on: [summarise]
  bash: |
    # conversationId for GitHub mentions is owner/repo#N — pass N in as $1
    gh pr comment "$1" --body-file "$ARTIFACTS_DIR/reply.md"
```

Archon prepends the hidden self-trigger marker automatically only on its **own** orchestrator-driven replies. If you post comments from a `bash:` node, append the marker yourself when the comment quotes Archon-style content, otherwise self-trigger guards may not catch it:

```bash
printf '\n<!-- archon-bot-response -->\n' >> "$ARTIFACTS_DIR/reply.md"
```

### Fetch failing CI logs for the current branch

```yaml
- id: ci-logs
  bash: |
    branch="$(git branch --show-current)"
    run_id="$(gh run list --branch "$branch" --status failure \
                --limit 1 --json databaseId --jq '.[0].databaseId')"
    if [ -n "$run_id" ]; then
      gh run view "$run_id" --log-failed > "$ARTIFACTS_DIR/ci-failed.log"
    else
      echo "no-failed-runs"
    fi
```

A downstream `prompt:` node can then read `$ARTIFACTS_DIR/ci-failed.log` and propose a fix.

### Reply to a single review thread (Python via `script:`)

```yaml
- id: resolve-thread
  script:
    runtime: uv
    deps: [requests]
    code: |
      import os, subprocess, json
      pr = os.environ["PR"]; tid = os.environ["THREAD_ID"]; body = os.environ["BODY"]
      subprocess.run(["gh","api","graphql","-f",
        f'query=mutation {{ addPullRequestReviewThreadReply(input: '
        f'{{ pullRequestReviewThreadId: "{tid}", body: "{body}" }}) '
        f'{{ comment {{ id }} }} }}'], check=True)
  env:
    PR: "$1"
    THREAD_ID: "$pick-thread.output"
    BODY: "Addressed in $WORKFLOW_ID"
```

## Notes

- `gh` honours `GH_TOKEN` and `GITHUB_TOKEN` env vars; either works.
- The worktree's git remote already points at the right repo when Archon created it from a registered codebase.
- Avoid `gh auth login` from inside a node — it expects an interactive terminal.
- For commands that print large output, write to `$ARTIFACTS_DIR/<file>` and have the next node read the file. Stdout is captured into the run's event log.
- `$BASE_BRANCH` is auto-detected from git when `worktree.baseBranch` is unset; safe to use in `gh pr create --base`.
