# 2.1 Install and verify

What this answers: how to install Archon, where its state lives on disk, and how to confirm the install with `archon doctor`.

## Install paths

| Mode | How | Notes |
|------|-----|-------|
| Native binary | curl installer or Homebrew (release artifact) | Self-contained. Bundled defaults are embedded. Needs `CLAUDE_BIN_PATH` in env or `assistants.claude.claudeBinaryPath` in config to spawn Claude. |
| Source build | `git clone` + `bun install` + `bun run dev` (or `bun link`) | Bundled defaults read from filesystem. Claude SDK resolves via `node_modules` — no `CLAUDE_BIN_PATH` needed. |

Always set `ARCHON_HOME` if you want a non-default location for state. Default is `~/.archon`.

## Where state lives

```
~/.archon/                           # User-level, ARCHON_HOME
├── workspaces/<owner>/<repo>/       # Per-codebase project layout
│   ├── source/                      # Cloned repo OR symlink to local repo
│   ├── worktrees/                   # Per-run worktrees
│   ├── artifacts/runs/<runId>/      # $ARTIFACTS_DIR — workflow outputs
│   ├── artifacts/uploads/<convId>/  # Web UI uploads (ephemeral)
│   └── logs/                        # JSONL workflow logs
├── workflows/                       # Home-scoped workflows (apply to every repo)
├── commands/                        # Home-scoped commands
├── scripts/                         # Home-scoped scripts (script: nodes)
├── vendor/codex/                    # Codex native binary (binary builds)
├── web-dist/<version>/              # Cached web UI bundle (binary + archon serve)
├── update-check.json                # Update check cache (24h TTL, binary builds)
├── archon.db                        # SQLite database (when DATABASE_URL not set)
├── config.yaml                      # Home config (non-secret defaults)
└── .env                             # Home env file (secrets, loaded at boot)
```

```
<repo>/.archon/                      # Repo-level, lives in your codebase
├── workflows/                       # Project workflows (override home by filename)
├── commands/                        # Project commands
├── scripts/                         # Project scripts
├── state/                           # Cross-run state (gitignored)
├── config.yaml                      # Repo overrides
└── .env                             # Repo env (loaded after home, overrides it)
```

The user-level `~/.archon/.env` loads first. The repo-level `<repo>/.archon/.env` loads after with override. The repo's own `<repo>/.env` (no `.archon/` prefix) is yours — Archon strips `CWD` from it at boot and never reads it.

## Database auto-detection

| `DATABASE_URL` | Backend | Init |
|----------------|---------|------|
| Unset | SQLite at `~/.archon/archon.db` | Auto-created on first start |
| Set | PostgreSQL at that URL | Run `psql $DATABASE_URL < migrations/000_combined.sql` once |

Switching is one env var. No data migration tool — the two backends are independent stores.

## Verify with `archon doctor`

`archon doctor` runs seven checks in parallel. Exits non-zero if any check fails.

| Check | What it does | When it skips | When it fails |
|-------|--------------|---------------|---------------|
| Claude binary | Spawns `$CLAUDE_BIN_PATH --version` (5s timeout) | Source builds (SDK resolves via node_modules) | Binary builds when `CLAUDE_BIN_PATH` unset or path doesn't spawn |
| gh CLI | Runs `gh auth status` (10s timeout) | No `GITHUB_TOKEN` and no `GH_TOKEN` set | Auth fails — fix with `gh auth login` |
| Database | Runs `SELECT 1` against the configured backend | Never skips | Module load error or query error |
| Workspace | Writes a probe file under `ARCHON_HOME` | Never skips | Directory not writable |
| Bundled defaults | Imports `BUNDLED_COMMANDS` and `BUNDLED_WORKFLOWS` | Never skips | Import error (stale binary or broken build) |
| Slack | `auth.test` against the Slack API (5s timeout) | No `SLACK_BOT_TOKEN` | Slack rejects the token; network errors are reported as skip |
| Telegram | `getMe` against the Telegram API (5s timeout) | No `TELEGRAM_BOT_TOKEN` | Telegram rejects the token; network errors are reported as skip |

If any check fails, `archon setup` re-runs the wizard.
