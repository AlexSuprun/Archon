# 4.1 Workflow file shape

What this answers: where workflow YAML files live, how they are discovered, and what top-level fields they must declare.

## File locations

| Source | Path | Scope |
|---|---|---|
| `bundled` | embedded in the Archon binary (`packages/workflows/src/defaults/`) | every install |
| `global` | `~/.archon/workflows/` (or `$ARCHON_HOME/workflows/`) | every project for current user |
| `project` | `<repoRoot>/.archon/workflows/` | one repo |

Files are discovered recursively, but **only one level of subfolder is loaded**. `~/.archon/workflows/triage/foo.yaml` works. `~/.archon/workflows/triage/nested/foo.yaml` is ignored silently.

Legacy path `~/.archon/.archon/workflows/` is not loaded. If detected, Archon emits a one-time warning with a `mv` command.

## Discovery order (precedence)

```
bundled  <  global  <  project
```

Same filename in a higher tier shadows the lower tier. The first hit by `name:` resolves the workflow.

## Validation

Run before invoking:

```
archon validate workflows               # all
archon validate workflows my-workflow   # single
archon validate workflows --json
```

Validation checks YAML parse, schema (Zod), DAG structure (cycles, unknown deps, dangling `$nodeId.output` refs), provider identity, and referenced resources (command files, MCP config files, skill directories).

## Top-level schema

Source: `packages/workflows/src/schemas/workflow.ts` (`workflowBaseSchema` + `workflowDefinitionSchema`).

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | yes | workflow identifier, used by `archon workflow run <name>` |
| `description` | string | yes | one-line summary |
| `nodes` | array | yes | DAG nodes (see 4.2) |
| `provider` | string | no | `claude` \| `codex` \| `pi` (or registered community id) |
| `model` | string | no | passed verbatim to SDK; not validated |
| `modelReasoningEffort` | enum | no | Codex: `minimal` \| `low` \| `medium` \| `high` \| `xhigh` |
| `webSearchMode` | enum | no | Codex: `disabled` \| `cached` \| `live` |
| `additionalDirectories` | string[] | no | extra dirs SDK can read |
| `interactive` | boolean | no | force foreground execution; required for approval-gate workflows on web UI |
| `effort` | enum | no | Claude: `low` \| `medium` \| `high` \| `max` |
| `thinking` | string \| object | no | Claude: `adaptive` \| `enabled` \| `disabled` or `{type, budgetTokens}` |
| `fallbackModel` | string | no | Claude only |
| `betas` | string[] | no | Claude only; non-empty |
| `sandbox` | object | no | Claude SDK SandboxSettings (passthrough) |
| `worktree.enabled` | boolean | no | pin worktree on/off; omit to defer to caller |
| `mutates_checkout` | boolean | no | default `true`; set `false` to allow concurrent runs on same path |
| `tags` | string[] | no | display only |

## Minimal example

```yaml
name: greet
description: Say hello and exit.
nodes:
  - id: hello
    prompt: "Greet the user briefly."
```

## Resolution chain

Provider for a node is resolved as: `node.provider ?? workflow.provider ?? config.assistant`. Model follows the same chain. Provider id is validated at load time; model strings are not.
