# 4.4 Variables and passing data

What this answers: every variable a workflow author can reference, where it's available, and what supplies its value.

Source: `packages/workflows/src/executor-shared.ts` (`substituteWorkflowVariables`) and `packages/workflows/src/utils/variable-substitution.ts`.

## Variable reference

| Variable | Scope | Value source |
|---|---|---|
| `$1`, `$2`, `$3`, … | every prompt-bearing field (`prompt`, `command` body, `loop.prompt`, `approval.message`, `bash`, `script`, `cancel`) | positional args after the workflow name on the command line |
| `$ARGUMENTS` | same as above | all args joined by space |
| `$nodeId.output` | downstream prompts and `when:` expressions | trimmed stdout (bash/script) or assistant final response (AI nodes); structured JSON if `output_format` was set |
| `$ARTIFACTS_DIR` | every prompt-bearing field | `~/.archon/workspaces/<owner>/<repo>/artifacts/runs/<runId>/` (pre-created by executor) |
| `$WORKFLOW_ID` | every prompt-bearing field | the workflow run uuid |
| `$BASE_BRANCH` | every prompt-bearing field | `worktree.baseBranch` from `.archon/config.yaml`, else auto-detected from git; **throws if referenced but unresolved** |
| `$DOCS_DIR` | every prompt-bearing field | `docs.path` from `.archon/config.yaml` (default `docs/`); never throws |
| `$LOOP_USER_INPUT` | loop node prompts (interactive) | text from `archon workflow approve <run-id> <text>`; **only on the first iteration after resume**, empty string otherwise |
| `$LOOP_PREV_OUTPUT` | loop node prompts | cleaned output of the previous iteration; empty on the first iteration |
| `$REJECTION_REASON` | `approval.on_reject.prompt` | text from `archon workflow reject <run-id> <reason>`; empty everywhere else |

## Edge cases

- **`$BASE_BRANCH` strictness.** The substitution layer scans the prompt for `$BASE_BRANCH`. If found and the value is empty (no `worktree.baseBranch` configured and git auto-detect failed), the run fails with a clear error. Avoid referencing it in prompts that don't need it.
- **`$LOOP_USER_INPUT` lifetime.** Populated only on the very first iteration after `archon workflow approve`. On all subsequent iterations of the same loop it is `''`. If you need durable feedback, write it to a file in `$ARTIFACTS_DIR` on iteration 1.
- **`$LOOP_PREV_OUTPUT` and `fresh_context: true`.** When a loop runs with `fresh_context: true`, each iteration starts a new SDK session. `$LOOP_PREV_OUTPUT` is the only carry-over. Use it to pass the previous draft, last error, or last completion signal.
- **`$REJECTION_REASON` scope.** Only substituted inside `approval.on_reject.prompt`. Elsewhere it resolves to `''`.
- **`$nodeId.output` after skip.** A skipped upstream node has `output: ''`. Downstream conditions referencing it compare against the empty string.
- **JSON field access.** `$classify.output` returns the full string; condition expressions support `$classify.output.type` for JSON field access. Plain prompt substitution does not — you get the raw JSON string.
- **`$ARTIFACTS_DIR` lifetime.** The directory exists for the duration of the run and persists after; it is the right place for files produced by one node and consumed by another.

## Passing data between nodes

```yaml
nodes:
  - id: classify
    prompt: |
      Classify "$ARGUMENTS" as one of: BUG, FEATURE, QUESTION.
      Output exactly one word.

  - id: bug-flow
    depends_on: [classify]
    when: "$classify.output == 'BUG'"
    prompt: "Triage the bug: $ARGUMENTS"

  - id: write-artifact
    depends_on: [classify]
    bash: |
      echo "type=$classify.output" > $ARTIFACTS_DIR/triage.txt

  - id: read-artifact
    depends_on: [write-artifact]
    prompt: |
      Read $ARTIFACTS_DIR/triage.txt and continue.
```

For structured data, use `output_format` (see 4.5) so downstream nodes can reliably parse `$nodeId.output.field` in `when:` expressions.
