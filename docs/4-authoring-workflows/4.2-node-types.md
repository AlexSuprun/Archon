# 4.2 Node types

What this answers: what each DAG node type does, what fields it takes, and what it produces.

Source: `packages/workflows/src/schemas/dag-node.ts`. A node must declare exactly one of: `command`, `prompt`, `bash`, `script`, `loop`, `approval`, `cancel` — these are mutually exclusive.

## Reference table

| Type | Purpose | Key fields | Executes | Output capture | AI? |
|---|---|---|---|---|---|
| `command` | run a named command file from `.archon/commands/` | `command:` (file name without `.md`) | command file body as prompt | assistant final response | yes |
| `prompt` | inline AI prompt | `prompt:` | string as prompt | assistant final response | yes |
| `bash` | shell script, no AI | `bash:`, `timeout:` (ms) | `/bin/sh -c` in cwd | stdout (trimmed) → `$nodeId.output` | no |
| `script` | TypeScript or Python script | `script:`, `runtime:` (`bun`\|`uv`), `deps:`, `timeout:` | `bun` or `uv run` | stdout → `$nodeId.output` | no |
| `loop` | iterate AI prompt until done | `loop.prompt`, `loop.until`, `loop.max_iterations`, `loop.fresh_context`, `loop.until_bash`, `loop.interactive`, `loop.gate_message` | repeats prompt until completion signal | last iteration's cleaned output | yes |
| `approval` | human gate | `approval.message`, `approval.capture_response`, `approval.on_reject` | pauses run | reviewer comment when `capture_response: true` | no |
| `cancel` | terminate run with reason | `cancel:` (string) | ends workflow | none | no |

Shared base fields on every node: `id`, `depends_on`, `when`, `trigger_rule`, `idle_timeout`, `retry`. AI nodes also accept `model`, `provider`, `context` (`fresh`\|`shared`), `output_format`, `allowed_tools`, `denied_tools`, `hooks`, `mcp`, `skills`, `agents`, `effort`, `thinking`, `maxBudgetUsd`, `systemPrompt`, `fallbackModel`, `betas`, `sandbox`. AI fields on `bash`/`script`/`loop` nodes are ignored with a warning.

## command

Loads a command file from `.archon/commands/<name>.md` (or bundled/global) and runs it as the prompt.

```yaml
- id: plan
  command: archon-plan
  depends_on: [classify]
```

## prompt

Inline prompt. Variable substitution applies (see 4.4).

```yaml
- id: summarize
  prompt: |
    Summarize $1 in 3 bullets.
  depends_on: [research]
```

## bash

Shell script. Stdout is captured for downstream `$nodeId.output`. Per-project env vars are injected.

```yaml
- id: lint
  bash: |
    bun run lint
  timeout: 120000
```

## script

TypeScript via `bun` or Python via `uv`. `runtime:` is required. `deps:` installs packages before run.

```yaml
- id: parse-json
  script: |
    import sys, json
    data = json.load(sys.stdin)
    print(data["title"])
  runtime: uv
  deps: []
  timeout: 30000
```

A named script in `.archon/scripts/foo.ts` can be referenced by name with `script: foo`.

## loop

Repeats `loop.prompt` until the AI emits the `loop.until` string (completion signal) or `loop.until_bash` exits 0. `max_iterations` caps the count. `fresh_context: true` starts a new session each iteration; use `$LOOP_PREV_OUTPUT` to pass the previous result.

```yaml
- id: refine
  loop:
    prompt: |
      Improve $DOCS_DIR/draft.md. Print COMPLETE when done.
      Previous: $LOOP_PREV_OUTPUT
    until: COMPLETE
    max_iterations: 5
    fresh_context: true
```

`retry:` is rejected on loop nodes — the loop manages its own iteration.

## approval

Pauses the run. Resume with `archon workflow approve <run-id> [comment]` or `archon workflow reject <run-id> <reason>`. Set `capture_response: true` to expose the comment as `$nodeId.output`. `on_reject.prompt` runs as a recovery branch (with `$REJECTION_REASON`).

```yaml
- id: gate
  depends_on: [plan]
  approval:
    message: "Plan looks good?"
    capture_response: true
    on_reject:
      prompt: "Revise the plan based on: $REJECTION_REASON"
      max_attempts: 3
```

## cancel

Ends the workflow run with a reason. Useful as a terminal branch behind a `when:` guard.

```yaml
- id: stop
  depends_on: [classify]
  when: "$classify.output == 'SKIP'"
  cancel: "Classifier returned SKIP — nothing to do."
```
