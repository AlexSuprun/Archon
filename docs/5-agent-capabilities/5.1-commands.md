# 5.1 Commands and slash commands

What this answers: which slash commands are deterministic vs AI-routed, and how command files plug into workflows.

## Two kinds of "command"

| Kind | Where | Triggered by | Deterministic? |
|------|-------|--------------|----------------|
| Slash command | Chat / Web UI input | User types `/foo` | Yes (handler) or No (orchestrator) |
| Command file | `.archon/commands/*.md` (or home, or bundled) | Workflow `command:` node | N/A — it's a prompt template |

These are unrelated systems that share the word "command." Slash commands are CLI verbs in chat. Command files are reusable prompt templates referenced from workflow YAML.

## Built-in slash commands

Top-level deterministic commands handled by `command-handler.ts` (no AI):

| Command | Purpose |
|---------|---------|
| `/help` | Show available commands |
| `/status` | Session, project, active workflow, worktree summary |
| `/reset` | Deactivate active session, clear context |
| `/commands` | List command files registered for the current codebase |
| `/init` | Create `.archon/` skeleton in current repo (config + example command) |
| `/worktree …` | Manage worktrees for the current conversation |
| `/workflow …` | Run, list, control workflows |

AI-orchestrated commands (parsed from orchestrator output, not switch-cases):

| Command | Purpose |
|---------|---------|
| `/register-project <name> <path>` | Register a local project |
| `/update-project <name> <path>` | Change a project's path |
| `/remove-project <name>` | Remove a project |

Anything else returns "Unknown command" with a pointer to `/help`.

## /workflow subcommands

| Subcommand | Effect |
|------------|--------|
| `list` (alias `ls`) | List workflows (project + home + bundled), shows broken YAML errors |
| `reload` | Re-discover workflow files |
| `run <name> [args]` | Start a run |
| `status` | Show all active runs for this conversation |
| `cancel` | Cancel the active run |
| `resume <id>` | Re-run a failed run, skipping completed nodes |
| `abandon <id>` | Mark a non-terminal run as cancelled |
| `approve <id> [text]` | Pass an approval gate; `text` is captured as `$<node>.output` when `capture_response: true` |
| `reject <id> <reason>` | Reject a gate; `reason` is exposed as `$REJECTION_REASON` to `on_reject` prompt |

`cleanup [days]` exists on the CLI only (`archon workflow cleanup`), not in chat.

## /worktree subcommands

| Subcommand | Effect |
|------------|--------|
| `create <branch>` | New worktree for this conversation; updates `cwd` |
| `list` | `git worktree list` for the active codebase |
| `remove [--force]` | Drop worktree; refuses if uncommitted changes (use `--force` to override) |
| `orphans` | Show worktrees with no DB record |
| `cleanup [merged]` | Remove stale or merged worktrees |

Branch names are restricted to `[a-zA-Z0-9_-]+`.

## Command files

Workflow `command:` nodes load a named prompt template from disk.

```
nodes:
  - id: plan
    command: planner       # → looks for "planner.md"
```

### Discovery

Search order (later wins for same name):

1. Bundled defaults — embedded in the binary via `bundled-defaults.generated.ts`. Source: `packages/workflows/src/defaults/commands/`. Disable with `defaults.loadDefaultCommands: false`.
2. Home — `~/.archon/commands/*.md` (or `$ARCHON_HOME/commands/`). Subfolders 1 level deep.
3. Project — `.archon/commands/*.md` in the repo root.

Project overrides home overrides bundled, by filename.

### File shape

Plain markdown. Optional YAML frontmatter for metadata (`description`). Body is the prompt. Variable substitution applies when invoked from a workflow:

| Variable | Source |
|----------|--------|
| `$1`, `$2`, `$3` | Positional args from the run invocation |
| `$ARGUMENTS` | All args joined |
| `$ARTIFACTS_DIR` | Pre-created per-run artifacts directory |
| `$WORKFLOW_ID` | Current run id |
| `$BASE_BRANCH` | Auto-detected if `worktree.baseBranch` unset |
| `$DOCS_DIR` | From `docs.path` in `.archon/config.yaml` (default `docs/`) |
| `$<nodeId>.output` | stdout / cleaned output of an upstream node |
| `$LOOP_USER_INPUT` | First iteration of a resumed interactive loop |
| `$LOOP_PREV_OUTPUT` | Previous loop iteration's cleaned output |
| `$REJECTION_REASON` | Reviewer text (only inside `on_reject` prompts) |

### Listing what's available

| Surface | How |
|---------|-----|
| Chat | `/commands` (codebase commands only) |
| HTTP | `GET /api/commands?cwd=…` returns `[{ name, source: 'bundled' \| 'project' }]` |
| CLI | `archon validate commands` |

Note: `GET /api/commands` reports `bundled` vs `project`. Home-scoped commands are merged into the same list.

### After editing bundled defaults

Run `bun run generate:bundled`. CI's `bun run validate` fails if the embedded bundle is stale.
