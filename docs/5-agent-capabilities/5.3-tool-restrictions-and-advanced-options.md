# 5.3 Tool restrictions and advanced options

What this answers: per-node and workflow-level knobs for tool whitelists, reasoning depth, sandboxing, budgets, model fallback, and beta flags.

## Options table

| Option | Providers | Values | Purpose |
|--------|-----------|--------|---------|
| `allowed_tools` | Claude | string[] of tool names | Whitelist tools the agent may call. Maps to SDK `tools`. |
| `denied_tools` | Claude | string[] of tool names | Blocklist. Maps to SDK `disallowedTools`. |
| `effort` | Claude | `low` \| `medium` \| `high` \| `max` | Claude SDK reasoning depth. |
| `thinking` | Claude | `adaptive` \| `enabled` \| `disabled` \| `{ type: enabled, budgetTokens }` | Claude extended-thinking config. Shorthand strings expand to `{ type: … }`. |
| `modelReasoningEffort` | Codex | `minimal` \| `low` \| `medium` \| `high` \| `xhigh` | Codex reasoning effort. Distinct from Claude `effort`. |
| `webSearchMode` | Codex | `disabled` \| `cached` \| `live` | Codex web search behavior. |
| `additionalDirectories` | Codex | string[] of absolute paths | Extra dirs the Codex CLI may read. |
| `sandbox` | Claude | object — see below | OS-level filesystem/network restrictions. |
| `maxBudgetUsd` | Claude | number > 0 | Cap total spend per run. SDK aborts when exceeded. |
| `fallbackModel` | Claude | model string | If primary `model` errors, retry with this one. |
| `betas` | Claude | non-empty string[] | Anthropic beta header values. |
| `systemPrompt` | Claude | string | Override the SDK system prompt for this node. |
| `mcp` / `hooks` / `skills` / `agents` | Claude | see 5.2 | Per-node integrations. |
| `output_format` | Claude (SDK enforced), Codex (SDK enforced), Pi (best-effort) | JSON Schema object | Force structured JSON output. |
| `provider` | All | `claude` \| `codex` \| `pi` | Override the resolved provider. |
| `model` | All | string | Forwarded verbatim to the SDK. Not validated. |
| `context` | Claude, Codex | `fresh` \| `shared` | New session vs continue prior. |
| `idle_timeout` | All | positive number (ms) | Abort node if no SDK activity. |
| `retry` | All (not on `loop`) | retry config | Step-level retry policy. |

Codex maps internally to `sandboxMode: 'danger-full-access'` and `approvalPolicy: 'never'` — Archon does not expose Codex sandbox toggles.

## Workflow-level vs per-node

Most options can be set at either level. Per-node beats workflow.

| Set on workflow | Set on node | Notes |
|-----------------|-------------|-------|
| `provider`, `model`, `effort`, `thinking`, `fallbackModel`, `betas`, `sandbox`, `interactive`, `modelReasoningEffort`, `webSearchMode`, `additionalDirectories` | Same plus `allowed_tools`, `denied_tools`, `mcp`, `hooks`, `skills`, `agents`, `systemPrompt`, `maxBudgetUsd`, `output_format`, `context` | Per-node merges with / overrides workflow-level on a field-by-field basis. |

Provider resolution chain: `node.provider` → `workflow.provider` → `assistants.*` in `.archon/config.yaml`. Model never affects provider selection.

`interactive: true` at the workflow level forces foreground execution on the web — required for approval-gate workflows in the Web UI.

## allowed_tools / denied_tools (Claude only)

Maps directly to SDK `tools` / `disallowedTools`. Tool names follow the SDK conventions: `Read`, `Write`, `Edit`, `Bash`, `Grep`, `Glob`, `Task`, `WebFetch`, `WebSearch`, `Skill`, and `mcp__<server>__<tool>` for MCP tools.

Notes:
- When `mcp:` is set, Archon appends `mcp__<server>__*` wildcards to `allowedTools` automatically. You don't list every MCP tool by hand.
- When `skills:` is set, Archon adds `Skill` to `allowedTools` automatically.
- Codex and Pi ignore both fields. To restrict tools on Codex, restrict at the OS / sandbox level upstream.

## thinking (Claude only)

```yaml
thinking: adaptive            # → { type: adaptive }
# or
thinking:
  type: enabled
  budgetTokens: 8000
```

Three states: `adaptive` (model decides), `enabled` (always on, optional `budgetTokens`), `disabled`.

## sandbox (Claude only)

OS-level restrictions passed through to the SDK. Schema is permissive (`.passthrough()`) — fields the SDK adds in future versions are accepted without an Archon update.

Common subsets:

```yaml
sandbox:
  enabled: true
  network:
    allowedDomains: [api.github.com, registry.npmjs.org]
    allowManagedDomainsOnly: true
  filesystem:
    denyWrite: ["**/node_modules/**", ".git/**"]
```

## maxBudgetUsd, fallbackModel, betas (Claude only)

- `maxBudgetUsd`: hard cap per run. The SDK aborts the node when exceeded.
- `fallbackModel`: the SDK retries the call with this model on certain errors. Useful for "try Opus, fall back to Sonnet on overload."
- `betas`: forwarded to the Anthropic API beta header. Non-empty array required.

## Validation

- Provider id is validated at load time. `provider: foo` rejects with `Unknown provider 'foo'. Registered: claude, codex, pi`.
- Model strings are NOT validated. Whatever you write is sent to the SDK.
- AI-only fields on `bash:` / `script:` / `loop:` / `approval:` / `cancel:` nodes are silently ignored at runtime with a warning. Defining them is harmless but pointless.
- `retry` is rejected on `loop:` nodes — loops manage their own iteration.
- `idle_timeout`, `timeout`, `maxBudgetUsd` must be finite and positive.

## Examples by intent

| Intent | Fields |
|--------|--------|
| Read-only research node | `allowed_tools: [Read, Grep, Glob, WebSearch]` |
| Block git push | `denied_tools: [Bash]` or sandbox `denyWrite` |
| Cap spend | `maxBudgetUsd: 5` |
| Force JSON handoff | `output_format: { type: object, properties: {...} }` |
| Heavy reasoning | Claude: `effort: high` + `thinking: enabled`. Codex: `modelReasoningEffort: high`. |
| Try premium then cheap | `model: opus`, `fallbackModel: sonnet` |
| Network-isolated build | `sandbox: { enabled: true, network: { allowManagedDomainsOnly: true } }` |
