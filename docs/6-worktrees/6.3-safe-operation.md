# 6.3 Safe operation

What this answers. The destructive commands Archon refuses to run, what happens when a worktree has uncommitted changes, and how to read isolation error messages.

## The `git clean -fd` ban

Archon never runs `git clean -fd` and you should not either, inside or outside Archon-managed worktrees.

| Why | What happens |
|-----|--------------|
| `-f` forces removal | No prompt, no confirmation |
| `-d` removes untracked directories | Deletes files git has never seen |
| Permanent | Not in any commit, not in reflog, not in stash |

Use instead:

| Goal | Command |
|------|---------|
| Discard tracked file changes | `git checkout .` |
| Discard staged changes | `git restore --staged .` |
| Inspect untracked files first | `git status` then delete by hand |
| Reset to a clean state safely | `git stash --include-untracked` (recoverable) |

## Uncommitted changes in a worktree

Git refuses to remove a worktree that has uncommitted changes. Archon surfaces the same refusal.

What you'll see:

```
Blocked: feature-auth
  ✗ uncommitted changes in worktree
  Use --force to override.
```

Recovery options, in order of safety:

1. `cd <worktree-path> && git status` — see what's there
2. Commit or stash the work, then re-run `archon complete <branch>`
3. If the diff is disposable, `archon complete <branch> --force`

`--force` skips every pre-flight check (uncommitted, active workflow, open PR, unmerged, unpushed). Use only when you've confirmed nothing is worth keeping.

## Isolation error categories

Errors during worktree creation pass through `classifyIsolationError`. Each pattern maps to one user-facing message.

| Pattern in error | Message you see | What to do |
|------------------|-----------------|------------|
| `permission denied` / `EACCES` | Permission denied while creating workspace | Check filesystem perms on `~/.archon/workspaces/` |
| `timeout` | Timed out creating workspace | Slow remote or stalled clone; retry, check network |
| `no space left` / `ENOSPC` | No disk space available | Free space; prune old worktrees and artifacts |
| `not a git repository` | Target path is not a valid git repository | Re-register codebase with a real repo path |
| `branch not found` | Branch may have been deleted or not pushed | Push the base branch or pick another with `--from` |
| `no base branch configured` | Set `worktree.baseBranch` or use `--from` | Add to `.archon/config.yaml` or pass `--from <branch>` |
| `belongs to a different clone` | Worktree was created by another local clone | Remove it from that clone, or re-register from same path |
| `cannot verify worktree ownership` | Cannot verify ownership at target path | Check perms; remove unrelated `.git` dirs at that path |
| `cannot adopt` | Refused to adopt existing directory | Remove target dir or pick a different branch |
| `submodule initialization failed` | Submodule init failed | Fix credentials/network or set `worktree.initSubmodules: false` |
| (none of the above) | `Could not create isolated workspace (<raw error>)` | Read the raw error; likely unhandled |

`isKnownIsolationError(err)` returns true for the first ten rows above. Unknown errors propagate as crashes rather than being absorbed as a soft "blocked" state.

## Recovering from an interrupted run

If the process dies mid-run (kill, crash, OS reboot), the worktree and branch persist.

| Symptom | Action |
|---------|--------|
| Run shows non-terminal status in `archon workflow status` | `archon workflow resume <run-id>` re-runs, skipping completed nodes |
| You don't want to retry | `archon workflow abandon <run-id>` marks it cancelled |
| Worktree exists but DB record gone | `archon isolation list` to confirm; remove with `git worktree remove` |

Archon does not auto-cancel workflow runs based on staleness. A run started by another process (web UI, GitHub mention, another CLI) cannot be safely declared dead from a different process. You decide via `abandon` or `resume`.

## Safe defaults

- Worktree-per-run is the default. Keep it on unless you know why you're opting out.
- `--force` exists for emergencies. Read the blocker list before using it.
- Prefer `archon complete` over manual `git worktree remove` + branch deletion — it keeps the DB in sync.
