# 2.3 Register your repos

What this answers: how to register a repository with Archon, what changes on disk in each case, and how to wire up multirepo (`~/Documents/code/`) vs single-repo GitHub setups.

## Two registration modes

`POST /api/codebases` takes exactly one of `url` or `path` (Zod-refined — both or neither is rejected).

| Mode | Body | What Archon does | Where the repo ends up |
|------|------|-------------------|------------------------|
| Clone | `{ "url": "https://github.com/owner/repo" }` | `git clone` into a managed source dir | `~/.archon/workspaces/owner/repo/source/` |
| Local path | `{ "path": "/abs/path/to/repo" }` | Validates `git rev-parse --git-dir`, registers in DB only | The original path you provided |

Notes from the implementation:

- A path that starts with `/`, `~`, or `.` passed to `url` is delegated to the local-path code path (no clone, no copy).
- If `GH_TOKEN` is set, clone URLs for `github.com` are rewritten to embed the token. Otherwise public clone only.
- If a clone target dir already exists with a matching repo URL in the DB, the request returns the existing codebase with `alreadyExisted: true` and HTTP 200 (vs 201 on fresh create).
- Local repos with no `origin` get `ownerName = "_local"` and use the directory name as `repoName`.

## What changes on disk

### Clone mode

```
~/.archon/workspaces/owner/repo/
├── source/         # git clone target (the repo itself)
├── worktrees/      # per-run worktrees go here
├── artifacts/      # workflow artifacts
└── logs/           # JSONL logs
```

Then `git config --global --add safe.directory <targetPath>` runs so subsequent git operations don't trip the safe-directory guard.

### Local path mode

The project layout (`worktrees/`, `artifacts/`, `logs/`) is created under `~/.archon/workspaces/<owner>/<repo>/` for tracking, but `source/` is NOT touched. The codebase row's `default_cwd` points at YOUR original path.

Worktrees are created relative to your repo. Nothing inside your repo is modified except the worktrees git mechanism creates and removes.

## CLI equivalent

There is no top-level `archon codebase add` command in the CLI. Use the Web UI or `curl` directly:

```
# Clone
curl -X POST http://localhost:3090/api/codebases \
  -H "Content-Type: application/json" \
  -d '{"url":"https://github.com/owner/repo"}'

# Register local
curl -X POST http://localhost:3090/api/codebases \
  -H "Content-Type: application/json" \
  -d '{"path":"/Users/me/Documents/code/svc-a"}'
```

## Endpoint reference

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/codebases` | List all registered codebases (de-duped) |
| GET | `/api/codebases/:id` | Fetch one codebase + its commands |
| POST | `/api/codebases` | Register (clone or local path) |
| DELETE | `/api/codebases/:id` | Remove from DB and clean up worktrees. Deletes the workspace dir on disk only if it sits under `~/.archon/workspaces/`; external local paths are left alone. |
| GET | `/api/codebases/:id/environments` | List tracked isolation environments |

## Decision: clone vs local path

| If your situation is... | Use |
|-------------------------|-----|
| Single GitHub project, you want Archon to own the working copy | Clone mode |
| Microservices under `~/Documents/code/<service>` you actively edit in your editor | Local path mode |
| Repo behind Bitbucket / non-GitHub, no token configured | Local path mode (clone yourself first, then register) |
| Need parallel runs + isolation but keep editing in your IDE | Local path mode — Archon makes worktrees off your repo, your live checkout stays untouched |

For multirepo work under `~/Documents/code/`, register each service as a local path. Worktrees live under `~/.archon/workspaces/<owner>/<repo>/worktrees/`, leaving your IDE checkout free of Archon-generated branches.
