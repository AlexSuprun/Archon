# 8.2 PR review and feedback

What this answers: how to wire a workflow that reads a PR diff, runs a review, posts inline comments, then reacts to reviewer feedback or CI failures.

## Pattern shape

```mermaid
flowchart LR
  trig[trigger<br/>@archon comment OR CI hook] --> diff[fetch-diff<br/>bash]
  diff --> review[review<br/>prompt + output_format]
  review --> post[post-comments<br/>bash]
  post --> wait{wait for<br/>reviewer / CI}
  wait -- reviewer comment --> fix1[apply-feedback<br/>loop]
  wait -- CI failure --> fix2[fix-ci<br/>loop]
  fix1 --> done[push + comment]
  fix2 --> done
```

Trigger is one of:

- `@archon review this` in a PR comment (Phase 7.1, comments only — descriptions ignored)
- A CI step that calls Archon (CircleCI for work, GitHub Actions for private). See 8.4 for bridging.

## Data flow

| Step | Input | Output | Used by |
|------|-------|--------|---------|
| fetch-diff | `$1` PR id (`owner/repo#N` or PR number) | unified diff on stdout | review |
| review | `$fetch-diff.output` | JSON `{comments: [{path, line, body, severity}], summary}` | post-comments |
| post-comments | `$review.output` | (side effect: comments on PR) | end / wait |
| apply-feedback | reviewer comments | code changes | push |
| fix-ci | CI logs | code changes | push |

## Integration touchpoints

| Concern | GitHub | Bitbucket |
|---------|--------|-----------|
| Fetch diff | `gh pr diff $1` | `curl -sS -u "$BB_USER:$BB_TOKEN" "$BB_BASE/2.0/repositories/$WS/$REPO/pullrequests/$1/diff"` |
| List PR comments | `gh api repos/{owner}/{repo}/pulls/{n}/comments` | `GET /2.0/repositories/.../pullrequests/{id}/comments` |
| Post inline comment | `gh api -X POST .../pulls/{n}/comments -f path=... -F line=... -f body=...` | `POST /2.0/repositories/.../pullrequests/{id}/comments` |
| Fetch CI logs | `gh run view <run-id> --log-failed` | CircleCI: `curl https://circleci.com/api/v2/project/.../job/{n}/output` |
| Auth | `GH_TOKEN` (gh CLI) | `BB_USER` / `BB_TOKEN`, `CIRCLE_TOKEN` via codebase env vars |

## Minimal skeleton

```yaml
name: pr-review
description: Read PR diff, post structured review, then react to feedback
provider: claude
interactive: true

nodes:
  - id: fetch-diff
    bash: |
      if [ -n "$BB_BASE" ]; then
        curl -sS -u "$BB_USER:$BB_TOKEN" \
          "$BB_BASE/2.0/repositories/$BB_WORKSPACE/$BB_REPO/pullrequests/$1/diff"
      else
        gh pr diff "$1"
      fi

  - id: review
    depends_on: [fetch-diff]
    prompt: |
      Review the diff. Flag bugs, security issues, and clear regressions only.
      Skip style nits. Return JSON.
      ---
      $fetch-diff.output
    output_format:
      type: json_schema
      schema:
        type: object
        required: [summary, comments]
        properties:
          summary: {type: string}
          comments:
            type: array
            items:
              type: object
              required: [path, line, body, severity]
              properties:
                path: {type: string}
                line: {type: integer}
                body: {type: string}
                severity: {type: string, enum: [info, warn, block]}

  - id: post-comments
    depends_on: [review]
    bash: |
      echo '$review.output' | jq -c '.comments[]' | while read -r c; do
        path=$(echo "$c" | jq -r .path)
        line=$(echo "$c" | jq -r .line)
        body=$(echo "$c" | jq -r .body)
        gh api -X POST "repos/${GH_OWNER}/${GH_REPO}/pulls/$1/comments" \
          -f path="$path" -F line="$line" -f side=RIGHT -f body="$body" \
          -f commit_id="$(gh pr view $1 --json headRefOid -q .headRefOid)" || true
      done
      gh pr comment "$1" --body "$(echo '$review.output' | jq -r .summary)"
```

### Variant: react to reviewer comments + CI failures

Add a second workflow `pr-fix` triggered from `@archon fix this` on the PR. Decide branch via `when:` on whether new review comments exist or whether the latest CI run failed.

```yaml
nodes:
  - id: gather-feedback
    bash: |
      gh api "repos/${GH_OWNER}/${GH_REPO}/pulls/$1/comments" \
        --jq '[.[] | select(.user.login != "archon-bot") | {path, line, body}]'

  - id: gather-ci
    bash: |
      RUN=$(gh run list --branch "$(gh pr view $1 --json headRefName -q .headRefName)" --limit 1 --json databaseId,conclusion -q '.[0]')
      echo "$RUN"
      if [ "$(echo $RUN | jq -r .conclusion)" = "failure" ]; then
        gh run view "$(echo $RUN | jq -r .databaseId)" --log-failed | tail -200
      fi

  - id: fix
    depends_on: [gather-feedback, gather-ci]
    loop:
      prompt: |
        Reviewer comments: $gather-feedback.output
        CI failure log: $gather-ci.output
        Address the highest-severity item, commit, and reply DONE when nothing remains.
      until: "DONE"
      max_iterations: 6

  - id: push
    depends_on: [fix]
    bash: |
      git push origin HEAD
      gh pr comment "$1" --body "Pushed fixes for review feedback and CI."
```

For CircleCI (work mode), replace `gather-ci` with `curl https://circleci.com/api/v2/project/bitbucket/$WS/$REPO/pipeline?branch=$BRANCH` and parse the failed job id; fetch step output with `GET /api/v2/project/.../job/{n}/output`.

## Failure modes

| Symptom | Cause | Fix |
|---------|-------|-----|
| `post-comments` posts every run, duplicates | No de-dupe on existing comments | Diff against `gh api .../comments` before posting; or only post the summary comment |
| Inline comment 422 `line not part of diff` | Line number outside the diff hunk | Skip lines not in diff; map to nearest hunk line |
| `output_format` JSON has extra prose | Pi best-effort mode | Wrap parse in `jq` with a fallback; or pin provider to Claude / Codex for this workflow |
| Token exhausted on huge diffs | Single-shot review of 5k-line PR | Split by file: `gh pr diff $1 --name-only` then loop per file |
| CI fix loop never converges | Wrong log scope, agent guessing | Pre-trim log to failing test names; pass test command in prompt |
| `@archon` mention not picked up | Webhook not configured, or mention in PR description | Move to a comment; verify webhook with `gh api` (Phase 7.2) |

Provider notes: `output_format` enforced on Claude and Codex; best-effort on Pi. `allowed_tools` / `denied_tools` and `hooks` are Claude-only — useful here to deny `Bash` in the `review` prompt so the agent cannot run code while reading the diff.
