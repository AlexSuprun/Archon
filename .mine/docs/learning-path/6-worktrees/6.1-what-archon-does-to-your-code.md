# 6.1 What Archon does to your code

What this answers. Where Archon puts files when you run a workflow, what branch it starts from, and how parallel runs avoid port conflicts.

## Default: one worktree per run

Every `archon workflow run` creates a fresh git worktree. Your live checkout is never touched. The worktree gets a new branch, runs the workflow, and stays on disk until you clean it up.

| Default | Behavior |
|---------|----------|
| Isolation mode | Worktree (always on, unless opted out) |
| Branch name | Auto-generated if `--branch` not given |
| Base branch | Auto-detected from `origin/HEAD` |
| Lifetime | Persists after run; cleaned up explicitly |

## Workspace layout

All worktrees, source clones, artifacts, and logs live under a single per-repo workspace.

```
~/.archon/workspaces/
└── <owner>/<repo>/
    ├── source/                  # cloned repo or symlink to local path
    ├── worktrees/
    │   ├── feature-auth/        # one directory per worktree branch
    │   ├── fix-1234/
    │   └── archon-run-abc123/   # auto-generated branches
    ├── artifacts/
    │   ├── runs/<run-id>/       # $ARTIFACTS_DIR for each run
    │   └── uploads/<conv-id>/   # Web UI file uploads
    └── logs/                    # JSONL workflow logs per run
```

Override the root with `ARCHON_HOME`. Default is `~/.archon`.

## Base branch resolution

Sync runs against `origin/<base>` before the worktree is created. Resolution order:

1. `worktree.baseBranch` in `.archon/config.yaml` (if set)
2. `git symbolic-ref refs/remotes/origin/HEAD` (the remote's default branch)
3. `origin/main` as last fallback

If none resolves, isolation creation fails with a `No base branch configured` error. Fix by setting `worktree.baseBranch` or passing `--from <branch>`.

`$BASE_BRANCH` in prompts uses the same resolution. It only fails the run if a prompt actually references it.

## Opting out of worktrees

Use `--no-worktree` to run in your live checkout. Appropriate when:

- The workflow only reads (assist, review, RCA on a checked-out branch)
- You want changes applied directly to the current branch
- The repo isn't a git repo (e.g. running on a sandbox path)

```bash
archon workflow run quick-fix --no-worktree "Fix typo in README"
```

Risks of `--no-worktree`:

- Workflow writes happen on whatever branch is currently checked out
- Parallel runs in the same checkout will conflict
- No clean rollback path; you own the diff

## Port allocation for parallel `bun dev`

Each worktree gets a deterministic, unique port so `bun dev` never collides with the main checkout.

| Setting | Value |
|---------|-------|
| Base port (main checkout) | `3090` |
| Worktree range | `3190` – `4089` |
| Hashing | MD5 of worktree absolute path → offset 100–999 |
| Determinism | Same worktree path always returns same port |
| Override | `PORT=4000 bun dev` (works in worktree and main) |

Logic lives in `packages/core/src/utils/port-allocation.ts`. The server detects worktree via `isWorktreePath(cwd)` and logs `worktree_port_allocated` with the chosen port on startup.

If `PORT` is set but invalid (not 1–65535), the server exits with code 1.
